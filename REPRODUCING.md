# Reproducing the result

Written for someone starting from a clean environment. The headline comparison
reproduces on **any OS** — Linux, Windows, macOS — because the runtime evidence
the agent depends on is captured once and committed as fixtures. A Mac is needed
only to re-capture that evidence yourself, which is optional and documented at
the end.

## What you need

| | |
|---|---|
| Python | 3.10 or newer (developed on 3.13.1) |
| Claude access | A Claude Code login **or** an `ANTHROPIC_API_KEY`. The Claude Agent SDK uses either. |
| Model | `claude-opus-5` for both arms |
| Disk | ~40 MB for the repo including fixtures |
| Optional, macOS only | Xcode 26+ and `xcodegen` (`brew install xcodegen`) to re-capture |

## Setup

```bash
git clone <this repo> && cd a11y-loop
python3 -m venv .venv
./.venv/bin/pip install -e ".[dev]"
```

Confirm the corpus and its answer key agree before spending anything on models.
This is the check that the ground truth is worth measuring against: every
seeded defect must fail its check on the broken source and pass it on the clean
source, and the trap must do the opposite.

```bash
./.venv/bin/python -m pytest tests/ -q
```

Expected: `48 passed`.

## Run the comparison

Both arms, scored against the same 24-case corpus:

```bash
./.venv/bin/a11y-loop eval
```

One arm at a time, if you would rather:

```bash
./.venv/bin/a11y-loop eval --only baseline
./.venv/bin/a11y-loop eval --only agent
```

Then render the table:

```bash
./.venv/bin/a11y-loop report
```

### What it does and what it costs

| Arm | What runs | Approx. time | Approx. cost |
|---|---|---|---|
| `baseline` | One prompt per screen, no tools, single pass | ~2.5 min | ~$1.40 |
| `agent` | Auditor → Fixer → Verifier per screen, plus one re-fix round | ~15 min | ~$10 |

Costs are what the Claude Agent SDK reported for our runs at `claude-opus-5`
and will vary a little with model routing. Both arms are re-runnable; each
starts from a fresh copy of the seeded app in `results/workspaces/`, so a rerun
never inherits the previous run's edits.

Output lands in:

- `results/baseline-source_only.json`, `results/agent.json` — per-case outcomes
- `results/workspaces/<arm>/` — the patched app each arm produced
- `trajectories/*.jsonl` — every agent's instructions, tool calls, tool results
  and final output

### Expected output

`a11y-loop report` prints the metric table followed by a per-case breakdown.
Model runs are not deterministic, so exact case-level results move between runs;
the shape that reproduces is the baseline passing the ordinary defects, and the
agent additionally resolving the cases that require the running app (`H01`,
`H02`) and declining the trap (`S06`). See `CHANGELOG.md` for the numbers we
measured and how each iteration moved them.

## Re-verify the repairs (macOS)

The portable checks decide the headline metric. On macOS you can make the
stronger claim: rebuild the patched app, re-run its UI tests, re-capture it in
the simulator and diff the audit results against the pre-repair capture.

```bash
./.venv/bin/a11y-loop verify --app agent
./.venv/bin/a11y-loop verify --app baseline-source_only
```

On a non-Mac this runs the portable checks and says so.

## Re-capture the evidence (macOS, optional)

The committed fixtures were produced by this, and running it should reproduce
them:

```bash
./.venv/bin/python eval/seed.py                              # rebuild the seeded app + ground truth
./.venv/bin/a11y-loop capture --app Ledgerly       --variant clean
./.venv/bin/a11y-loop capture --app LedgerlySeeded --variant seeded
```

Each capture builds the app, drives it through five screens twice — once at the
default text size and once at AX XXL — records Apple's accessibility audit and
the accessibility tree per screen, and writes them to `fixtures/<app>/<variant>/`.
Roughly 4 minutes per app on an M-series Mac, no API cost.

## The data

Everything the evaluation uses is in the repo:

- `corpus/Ledgerly/` — the clean app (written for this project, MIT)
- `corpus/LedgerlySeeded/` — generated by `eval/seed.py`, never hand-edited
- `eval/seeds.py` — every seeded defect as an exact, inspectable transformation
- `eval/ground_truth.json` — generated answer key: 24 cases, 22 scored
- `fixtures/` — the captured runtime evidence

No private data, no credentials, no third-party app code.
